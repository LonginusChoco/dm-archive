# DM Archive — クラシックレギュレーション カード検索ツール

`index.html` と `duelmasters.db` の2ファイルだけで動く、サーバー不要の
カード検索ツールです。ブラウザ上で `duelmasters.db`（SQLiteファイル）を
直接読み込んで動作します。

## ローカルで動作確認する場合

`index.html` をダブルクリックして直接開くと、ブラウザのセキュリティ制限
（CORS）により `duelmasters.db` を読み込めずエラーになることがあります。
その場合は、このフォルダで簡易サーバーを起動してから開いてください。

```
python -m http.server 8000
```

起動後、ブラウザで `http://localhost:8000/` を開いてください。

## GitHub Pagesで公開する手順

友人にURLで共有したい場合は、GitHub Pagesを使うのが簡単です。無料で、
今後ファイルを更新すれば同じURLに自動で反映されます。

### 1. GitHubアカウントを作る（まだの場合）
https://github.com/ にアクセスし、無料アカウントを作成してください。

### 2. 新しいリポジトリを作る
1. 右上の「+」→「New repository」
2. Repository name を決める（例: `dm-archive`）
3. 「Public」を選択（Pagesは無料枠だとPublicリポジトリのみ対応）
4. 「Create repository」

### 3. ファイルをアップロードする
作成したリポジトリのページで、
1. 「Add file」→「Upload files」
2. `index.html` と `duelmasters.db` の2ファイルをドラッグ＆ドロップ
3. 「Commit changes」

### 4. GitHub Pagesを有効にする
1. リポジトリの「Settings」タブを開く
2. 左メニューの「Pages」を開く
3. 「Build and deployment」の「Source」を「Deploy from a branch」に設定
4. 「Branch」を `main`（ブランチ名は環境により `master` の場合もあります）、
   フォルダを `/ (root)` にして「Save」

数分待つと、ページ上部に公開URLが表示されます
（例: `https://あなたのユーザー名.github.io/dm-archive/`）。
このURLを友人に伝えれば、スマホ・PCどちらのブラウザからも閲覧できます。

### 5. 今後の更新方法
`index.html` や `duelmasters.db` を更新したら、同じリポジトリのページで
再度「Add file」→「Upload files」で上書きアップロードし、
「Commit changes」するだけです。数分後には同じURLに反映されます。
友人に改めてファイルを送る必要はありません。

## ファイル構成

- `index.html` … 検索ツール本体（HTML/CSS/JS一式）
- `duelmasters.db` … カードデータベース（SQLite）
- `verify_image_urls.py` … 画像URLの検証・修正スクリプト（下記参照）

`duelmasters.db` を更新した場合は、このファイルだけを差し替えれば
反映されます（`index.html` 側の変更は不要です）。

## 画像URLの検証・修正について

一部のカード（"V"から始まる特殊なカード番号を持つカード等）は、画像ファイル名が
通常と異なる（末尾に`a`が付く等）ことが判明しました。`verify_image_urls.py`で、
全カードの画像URLが実際に正しいか確認し、DBを修正できます。

```
pip install requests --break-system-packages
python verify_image_urls.py --db duelmasters.db
```

全6,331枚を1件ずつHTTPで確認するため、**30分〜1時間程度**かかります。
実行後、修正された`duelmasters.db`をこのフォルダに配置し直せば、
`index.html`側のクライアント側での再試行処理に頼らずとも、最初から
正しい画像が表示されるようになります（`index.html`側の再試行処理自体は、
念のための保険としてそのまま残しています）。

## サイキック・クリーチャー系カードの裏面データについて

一部の「サイキック・クリーチャー」「サイキック・スーパー・クリーチャー」
系統のカードは、両面印刷されたカードです。以前のバージョンでは裏面
情報が欠落しているだけでなく、表面のコスト・パワー等が裏面の値に
汚染されて保存されるという重大な不具合がありました。

`refetch_dual_sided_cards.py`（メインのdm_classic_dbフォルダ側にあります）
で対象108枚を再取得すると、表面データが正しい値に修正され、
`index.html`のカード詳細モーダルにも裏面情報（画像・能力テキスト・文明・
コスト/パワー・種族）が表示されるようになります。

## 現状、未実装・既知の制約

- **フォーマット絞り込み**：データが未収集のため、絞り込み項目に含めていません
- **プロモカードの発売年**：年単位の近似値です（詳細は元のREADME参照）
- カードが公式サイトのデータベースに存在しない一部の古い商品
  （`DMC-01`〜`04`等、詳細は元のREADME参照）は検索結果に含まれません
- サイキック・クリーチャー系108枚について、`refetch_dual_sided_cards.py`
  を実行するまでは、表面のコスト・パワー等が誤ったままになっています

## 低解像度画像の調査について(2026-09-01)

一部のカードは、公式サイト自体に登録されている元画像のピクセルサイズが
非常に小さい（実機確認例: 650×909pxが標準のところ、137×191pxしかない
カードがあった）ことが判明しました。「裏面だから」「古いカードだから」
といった単純な規則性ではなく、個別のカードに点在しているようです。

`check_image_resolution.py`で、全カードの表裏画像を実際にダウンロードして
ピクセルサイズを確認し、閾値（既定300px）を下回るものを一覧化できます。

```
pip install requests Pillow --break-system-packages
python check_image_resolution.py --db duelmasters.db
```

全カードの画像を実際にダウンロードして確認するため、`verify_image_urls.py`
よりも時間がかかります（画像1枚あたりのデータ量が大きいため）。完了すると
`low_res_images.log`に該当カードの一覧が出力されます。

この一覧が出た後、それぞれについて公式サイト内に別の高画質版が無いか
個別に確認する必要があります。もし公式サイト自体にしか元データが無く、
それ自体が低解像度なのであれば、正直なところ「差し替え」自体が難しい
可能性があります。その場合は表示側で無理に引き伸ばさない対応を検討します。

## 手動での画像差し替えについて(2026-09-01)

`images/`フォルダには、公式サイトの元画像が低解像度・低画質だった177枚
について、ユーザーが手動で用意した高画質版を格納しています。該当する
カードのDB上の`image_url`（DMC-62のみ`image_url`のみ、他は必要に応じて
`back_image_url`も）は、公式サイトへの外部リンクではなく、この
`images/`フォルダ内のファイルを指すよう更新済みです。

`index.html`は画像URLをそのまま`<img src>`に使う実装のため、相対パスに
変わっていても**コード側の変更は不要**です。GitHub Pagesにアップロード
する際は、`index.html`・`duelmasters.db`に加えて**`images/`フォルダ
一式も必ず一緒にアップロード**してください。

対象:
- プロモ5〜9期（43枚）
- DMR-05のうち、カード番号末尾が「m」でないもの（121枚）
- DMX-13の25〜36番（12枚）
- DMC-62 1/18（表面のみ。裏面は画質良好のため元のまま）

今後さらに手動差し替えしたいカードが見つかった場合は、
`apply_manual_image_replacements.py`と同じ要領で追加できます
（`image_replacement_list.csv`を新しい対象で作り直すか、直接SQLで
`image_url`を更新してください）。
